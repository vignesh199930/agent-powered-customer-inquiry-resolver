# Design Decisions

## 1. Technology Stack

I chose Node.js with Express.js for the backend and HTML, CSS, and vanilla JavaScript for the frontend.

This stack was selected because it is lightweight, easy to set up, and suitable for the scope of this take-home assignment. Using vanilla JavaScript also keeps the application simple and avoids unnecessary dependencies.

## 2. Agent Architecture

The application follows a simple got programmatic agent workflow:

Customer Inquiry
→ Inquiry Classification
→ Information Retrieval
→ Response Generation
→ Final Response

The backend processes each inquiry through these stages before returning the response to the frontend.

## 3. Inquiry Classification

The application uses predefined topics and keyword matching to identify the primary intent of a customer inquiry.

Supported topics are:

- Pricing
- Technical Support
- Account Management
- General Information

The inquiry is normalized to lowercase before keyword matching to make the classification case-insensitive.

## 4. Information Retrieval

A hardcoded knowledge base stores topic-specific information and keywords.

Once a topic is identified, the agent retrieves the corresponding information from the knowledge base. This simulates a basic retrieval step without requiring a database or external service.

## 5. Response Generation

The final response is generated by combining a standard response template with the retrieved information.

This approach was chosen to demonstrate a simple end-to-end agent workflow while keeping the implementation deterministic and easy to understand.

## 6. Trade-offs

Keyword matching is simple and predictable, but it has limitations. It may not correctly understand complex language, synonyms, or inquiries containing multiple intents.

A more advanced implementation could use semantic similarity, confidence scoring, or an LLM-based classifier. However, the assessment explicitly prohibits external LLMs and APIs, so a programmatic approach was used.

## 7. Error Handling

Basic input validation is implemented to prevent empty or invalid inquiries from being processed.

The frontend also handles API errors and provides feedback to the user.

## 8. Future Improvements

Possible future improvements include:

- Confidence scoring for classification
- Support for multiple intents
- More advanced keyword matching
- External or database-backed knowledge base
- Automated unit and integration tests
- More contextual response templates
